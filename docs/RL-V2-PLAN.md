# План RL v2

Зафиксирован 22 октября 2026 до запуска. Только окно selection; confirmation (уже использован) и final test не оцениваются.

## Что меняется относительно RL v1

| | v1 | v2 |
|---|---|---|
| Политика | GPT-2 с одной целью, NDCG 0,065 | GPT-2 с PPS и откликом во входе, `pps-20261022-01/full+pps+fb/last.pt`, NDCG 0,147 |
| Награда | RM v1: MAE 0,345, PairAccuracy 0,506 | RM v2 (`reward-v2-20261022-01`): seeds 0 и 1 — proxy для обучения, seed 2 — отложенный судья |
| Метод | REINFORCE, 1 sample, 500 шагов, lr 1e-5; KL 0,003–0,13 | Точный градиент по всем 50 000 действиям; обучение до плато |
| Офлайн-метод | нет | Exp-RSFT / AWR по наблюдённой награде |

## Методы

1. **Reference** — исходная политика без изменений.
2. **Продолжение SFT** — тот же рецепт на всех позициях, вес 1, столько же шагов, сколько у Exp-RSFT. Контроль «эффект от дополнительного обучения».
3. **KL-RL с точным градиентом.** Для контекста h: J = Σ_a π(a|h) r(h,a) − β·KL(π(·|h) ‖ π_ref(·|h)), сумма по всем действиям каталога (expected policy gradient, Ciosek & Whiteson, AAAI 2018: ожидание по действиям вместо одного sample). Награды из кеша RM, посчитанного заранее для фиксированного набора train-контекстов.
   - completion: среднее seeds 0,1;
   - seconds: completion × min(длина, 600)/600;
   - completion-LCB: среднее − |r0 − r1|/2 (консервативная цель по ансамблю, Coste et al., ICLR 2024).
   - β ∈ {0,01; 0,03; 0,1; 0,3; 1}.
4. **Аналитический оптимум** π* ∝ π_ref·exp(r/β) на тех же оценочных контекстах — потолок proxy-цели при H=1 и контроль «нужно ли обучение».
5. **Exp-RSFT** (Chidambaram et al., arXiv 2603.10279, 2026; AWR, Peng et al., 2019): SFT на всех позициях логов с весом цели w = min(exp((r − V)/λ), 20), нормированным на средний вес батча. r — наблюдённая доля дослушивания цели (или seconds-версия), V — средняя доля дослушивания в префиксе контекста (зависит только от состояния). λ ∈ {0,1; 0,3; 1} для completion, λ = 0,3 для seconds. Модель награды не используется.

## Оценка (все политики, одинаково)

- Ожидаемая награда по полному каталогу на всех 1000 warm-пользователях: proxy (seeds 0,1), **судья seed 2**, ансамбль из 3; completion и seconds.
- Точный KL к reference.
- Релевантность на 492 активных: NDCG@10, Recall@10, HitRate@10; парный bootstrap против reference; 5%-допуск через нижнюю границу mean(NDCG − 0,95·NDCG_ref).
- **PairAccuracy политики на реальных исходах**: для пар прослушиваний одного пользователя в selection-дне с разницей доли ≥0,5 — доля пар, где политика даёт больше вероятности лучше дослушанному. Модель награды не участвует.
- Поведение: доли недавних/старых/новых в top-10, уникальные треки, доля самого частого, средняя длина и популярность top-10, награда судьи для top-10.
- Кривая переоптимизации: прирост proxy и прирост судьи против √KL для RL и аналитического оптимума.

## Правило вывода

Победителя по selection не объявляем; это исследовательская карта компромисса. Признаки взлома награды: proxy растёт, судья и PairAccuracy на реальных исходах — нет. Судья обучен на тех же логах и не является истиной: согласие proxy и судьи не доказывает пользу. Финальный тест — один раз, после фиксации кандидатов в отдельном документе.

## Дополнительные награды и запуск

Две новые цели для RM v2 (`recsys/targets.py`, `reward_v2.py --target`), обе только из логов:

- **continuation** — сколько ещё прослушиваний >50% будет строго позже в той же сессии (паузы ≤20 мин), максимум 10, /10. События на или после границы периода не считаются (правое цензурирование): обучающие метки не заглядывают за train end.
- **quantile** — перцентиль прослушанных секунд среди строго более ранних прослушиваний пользователя в той же log2-корзине длины трека (OneRec-V2, duration-aware shaping); 0,5 при <5 ранних прослушиваниях.

Для continuation Exp-RSFT не запускается: средняя метка префикса смотрела бы вперёд, за момент состояния.

Проверено на Mac (CPU, маленькие случайные модели-заглушки, настоящие данные): `rl_v2` и `reward_v2` для всех трёх целей проходят от начала до конца; 61 из 62 тестов (тест реранкера на Mac не загружается без `libomp`, на Windows проходил).

Запуск на ПК одной задачей, по очереди: тесты → RL completion → RM continuation → RL continuation → RM quantile → RL quantile. Оценка времени 2,5–3 часа.

```bash
python3 scripts/windows.py sync
python3 scripts/windows.py exec scripts/start-rl-v2-pipeline-windows.ps1
```
