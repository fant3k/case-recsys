# Глоссарий проекта

Термины, которые встречаются в [отчёте](../report/REPORT.md) и документах проекта.

## Модели

| Термин | Что значит у нас |
|---|---|
| **GPT-2** | Архитектура трансформера из языковых моделей. Токены — не слова, а ID треков: модель читает историю прослушиваний и предсказывает следующий трек |
| **Next-item prediction** | Задача «предсказать следующий объект», на которой обучается GPT-2 |
| **SFT** (supervised fine-tuning) | Обычное обучение с учителем на реальных историях, до RL |
| **Политика (policy), π** | Модель, которая выдаёт распределение вероятностей по всем 50 000 трекам. Рекомендация — 10 треков с наибольшей вероятностью |
| **Опорная политика, π_ref (reference)** | Исходная GPT-2 (с PPS и откликом во входе) до RL; точка отсчёта. RL не даёт уйти от неё слишком далеко |
| **PPS** | Приоритет повторов (Abbattista et al., RecSys 2024): к логиту трека прибавляется log(1 + count/0,01), где count — число его прослушиваний в последних 128 событиях. Из-за этого окна GPT-2 не видит старые любимые треки (раздел 2), а при многошаговой генерации засчитывает свои рекомендации как прослушивания (раздел 7) |
| **Отклик во входе (feedback)** | Модель видит не только какие треки играли, но и насколько их дослушали и какие были паузы |
| **Модель награды (RM, reward model)** | Отдельная сеть, которая по истории предсказывает отклик на трек — по умолчанию долю дослушивания |
| **Попарные признаки «пользователь–трек»** | Признаки кандидата, зависящие от пары: сколько раз этот человек слушал этот трек, как давно, как его дослушивал. Модель награды получает их явно. У GPT-2 счётчик повторов уже входит в PPS, но точная прошлая доля дослушивания пары отдельным признаком выходу не передаётся |
| **Ансамбль** | Несколько моделей награды с разными seed; ответ — их среднее |
| **Судья (judge)** | Модель награды seed 2, которая не входит в награду обучения политики; расхождение с ней — диагностика чувствительности, а не независимая истина |
| **Реранкер (LightGBM)** | Двухступенчатый метод: отбор кандидатов, затем градиентный бустинг на 21 признаке повторов. Лучший метод на наших данных |
| **Частота, частота + давность, память 50/50** | Простые ориентиры: рекомендовать то, что человек чаще слушал в последних 128 событиях (равенства — по ID или по давности) или в смеси последних 128 событий и всей истории |

## RL и оптимизация

| Термин | Что значит у нас |
|---|---|
| **RL** (обучение с подкреплением) | Дообучение политики так, чтобы она выбирала треки с большей предсказанной наградой |
| **Награда (reward), r** | Прогноз модели награды. Четыре варианта: доля дослушивания; нормированные «секунды» для обучения (доля × min(длина, 600)/600); продолжение сессии; квантиль дослушивания |
| **Градиент** | Направление, в котором нужно сдвинуть веса модели, чтобы улучшить цель. Обучение — много маленьких шагов по градиенту |
| **REINFORCE** | Простейший метод RL: выбрали трек, получили награду, сдвинули вероятность выбранного трека пропорционально награде. Градиент шумный (RL v1, E2) |
| **Точный градиент ожидания** | Суммирование по всем 50 000 трекам устраняет случайность выбора действия (RL v2); выбор батчей контекстов остаётся случайным |
| **KL-дивергенция, KL** | Мера того, насколько распределение политики отличается от опорного; 0 — не отличается |
| **β (бета)** | Вес штрафа за KL. Малое β — политика гонится за наградой и уходит далеко; большое β — остаётся близко к исходной |
| **Цель J** | J = ожидаемая награда − β·KL. Её максимизирует RL |
| **Аналитический оптимум, π*** | Точное решение этой цели без обучения: π* ∝ π_ref · exp(r/β) — перевзвешивание ответов исходной модели |
| **Перевзвешивание топ-50 (кандидат A)** | Тот же оптимум, но модель награды применяется только к 50 лучшим трекам — при выдаче, без изменения весов |
| **Кандидат B** | RL-политика с наградой «секунды», β = 0,3; вторая гипотеза финального теста |
| **Обратная / прямая KL, Джеффрис** | Три способа мерить расстояние до оптимума при обучении (RL v3): обратная — обычный RL, прямая — дистилляция оптимума, Джеффрис — их среднее |
| **Голова с попарными признаками (E1)** | Маленькая сеть над замороженной политикой, поправляющая логиты 50 лучших треков по их признакам; обучена той же целью RL |
| **Exp-RSFT** | Обучение с учителем, где примеры с высокой наблюдённой наградой весят больше; работает без модели награды |
| **Доля прироста J (share)** | Какую часть выигрыша оптимума получила обученная политика: 1 — всё, 0 — ничего |
| **Переоптимизация модели награды** | Политика усиливает ошибки конкретной модели награды; расхождение с отложенным судьёй может быть признаком этого, но не гарантирует обнаружения (Gao et al., 2023; Coste et al., 2024) |
| **Взлом спецификации (specification gaming)** | Сама формула награды поощряет нежелательное, например длинные треки в «секундах»; судья этого не ловит (Skalse et al., 2022) |
| **Симулятор отклика** | Модель, которая придумывает реакцию пользователя на сгенерированный трек |

## Метрики

| Термин | Что значит у нас |
|---|---|
| **NDCG@10** | Основная метрика: насколько высоко в топ-10 стоят треки, которые человек завтра реально дослушал больше чем наполовину; от 0 до 1 |
| **Recall@10** | Какую долю завтрашних дослушанных треков мы угадали в топ-10 |
| **HitRate@10** | Доля пользователей, у которых угадан хотя бы один трек |
| **PairAccuracy** | Для двух прослушанных треков одного человека с разницей доли ≥ 0,5: правильно ли оценка угадала, какой дослушан лучше; 0,5 — монетка. Считается по всем событиям дня или внутри топ-50 кандидатов политики |
| **AUC внутри топ-50** | Насколько хорошо оценка отделяет кандидатов из топ-50 политики, которых человек завтра дослушает больше чем на 50%, от остальных кандидатов топ-50; 0,5 — случайно |
| **MAE, RMSE** | Средняя ошибка прогноза доли дослушивания; меньше — лучше |
| **Эквивалентные секунды** | Прогноз доли × длина трека (до 600 с) — «сколько секунд дослушают» по модели |

## Протокол и статистика

| Термин | Что значит у нас |
|---|---|
| **Train / selection / confirmation / final test** | Четыре окна по времени: обучение, подбор, однократная промежуточная проверка, однократная финальная проверка |
| **Утечка (leakage)** | Модель случайно видит будущее; защита — данные строго до среза по времени |
| **Warm / активные пользователи** | Warm — есть история до среза (1000); активные — есть хотя бы одно дослушивание завтра (около 500) |
| **Bootstrap, 95% интервал** | Пересчёт по случайным подвыборкам пользователей, чтобы понять разброс оценки |
| **Поправка Бонферрони** | В финальном тесте две гипотезы, поэтому интервалы 97,5% вместо 95%. H2 состоит из двух условий, которые должны выполниться оба (тест intersection-union), и отдельной поправки внутри H2 не требует |
| **Допуск 5%** | Релевантность считается сохранённой, если нижняя граница интервала mean(NDCG − 0,95·NDCG_ref) ≥ 0 |
| **Пререгистрация, манифест SHA256** | Гипотезы и хэши файлов записаны до открытия финального окна, чтобы зафиксировать выбранные условия и обнаружить последующие изменения файлов |
| **Исследовательский опыт** | Поиск или описательный расчёт на уже использованном окне selection, до или после final; сам по себе не является независимым подтверждением |
| **Seed** | Начальное число генератора случайности; фиксируется для воспроизводимости |
| **FP16 / FP32** | Точность чисел на видеокарте: половинная и полная |
