# Модельно-независимая проверка исхода: что пользователи реально слушали

Статус: план, написан до запуска (25 октября 2026). Только окно selection; confirmation, final и новая когорта не читаются (в коде нет такой опции).

## Зачем

Выводы про H2 («прогнозируемые секунды выросли при сохранении NDCG») опираются на модели награды: обучающую и судью того же семейства. Здесь те же величины берутся из логов: сколько секунд пользователь реально слушал треки из нашей выдачи в окне меток. Это не заменяет онлайн-проверку, но не зависит от RM.

## Что считается

Для каждого warm-пользователя и каждого метода (опорная политика, A = перевзвешивание топ-50 по RM, B = RL «секунды» β = 0,3, личная частота) по top-10:
- `replay_seconds` — сумма по рекомендованным трекам реально прослушанных секунд (доля прослушивания × min(медианная длина в train, 600)) за окно меток;
- `replay_plays` — число прослушиваний рекомендованных треков в окне;
- средняя доля дослушивания среди прослушанных рекомендованных треков (условно на попадание, смещена по построению).

Парный bootstrap по пользователям против опорной политики (95%). Показываем два набора: все warm-пользователи и пользователи, слушавшие что-либо в окне.

## Как читать (задано заранее)

- Если для B интервал `replay_seconds` − опорная строго выше нуля, прогноз судьи о росте секунд подтверждён реальным логом; если интервал содержит ноль или ниже, прогноз судьи нельзя считать подтверждённым исходом, и в отчёте это пишется прямо.
- Для A то же по `replay_plays` и `replay_seconds`.
- Оценка условна: пользователь мог слушать только то, что ему показали и что он нашёл; не показанные треки в расчёте нулевые. Причинного вывода о пользе нет.
- Один день, один seed, selection использовалось многократно: числа исследовательские.
