Запуск `rl-v2-20261023-01`, Windows, 23 октября 2026, 3313 с, шаг `rl_completion` цепочки `Debug-RLv2-Pipeline-20261023-01` (тесты перед ним прошли). План до результатов — [RL-V2-PLAN](RL-V2-PLAN.md). Только selection; confirmation и final test не оценивались. Окно selection теперь оценено для 36 политик: выбор лучшей по нему оптимистичен, кандидаты для финального теста нужно зафиксировать отдельно.

Политика: GPT-2 + PPS + отклик (`pps-20261022-01/full+pps+fb/last.pt`), NDCG@10 0,1473. Обучающая награда — среднее RM v2 seeds 0 и 1, судья — seed 2. Ожидаемая награда — по всем 1000 warm-пользователям, NDCG — по 492 активным. «5%» — нижняя граница bootstrap-интервала mean(NDCG − 0,95·NDCG_ref) ≥ 0. PairAccuracy политики — на реальных прослушиваниях selection-дня, без RM.

## Выводы

1. **Перевзвешивание исходной политики моделью награды улучшило и награду, и релевантность.** Аналитический оптимум π* ∝ π_ref·exp(r/β) с RM v2 при β=0,03: NDCG +7,6% (нижняя граница разницы +0,006), награда +3,6% по обучающей RM и +3,0% по судье, PairAccuracy на реальных исходах 0,531 → 0,540. Это не утечка: RM видит только историю до среза; метод применим при выдаче (оценка всех 50 000 кандидатов на запрос), но это перевзвешивание на декодировании, а не обученная политика. Вероятное объяснение: признаки RM v2 (средняя доля дослушивания пары пользователь–трек, давность) переупорядочивают знакомые треки — ровно то, в чём GPT-2 слаба (см. [диагностику](GAP-DIAGNOSTICS-RESULTS.md)).
2. **Обученный RL переносит лишь часть этого выигрыша на новые контексты.** При β=0,01–0,03 RL получает 33–45% аналитического прироста цели и теряет NDCG (−1,2…−9,2%), PairAccuracy не растёт. Сеть обучена на 8192 train-контекстах и должна воспроизвести предпочтения RM на незнакомых. Оптимизация точным градиентом сходится (кривые в report.json), значит ограничение — в обобщении, а не в шуме градиента, как было в v1.
3. **«Секунды» — игра спецификацией, а не ошибка RM.** При малом β выдача схлопывается: 427–705 уникальных треков вместо 6658, 92–94% мест — новые для пользователя длинные треки (580 с), NDCG ≈ 0. Судья согласен с обучающей RM (+183% против +181%), потому что выигрыш даёт множитель длины в самой формуле награды. Ансамбль RM ловит только ошибки модели награды, а не неудачное определение награды; это видно по метрикам поведения (длина, новизна, уникальные треки).
4. **Лучший компромисс RL — секунды при β=0,3:** +6,7% предсказанных секунд (обучающая RM и судья одинаково) при −0,6% NDCG; 5%-допуск поддержан на selection. Аналитический оптимум даёт почти то же (+7,8% / −0,5%).
5. **Консервативная награда** (среднее − разброс ансамбля) ведёт себя как обычная: при двух моделях разброс мал (среднее 0,036) и почти не меняет порядок.
6. **Офлайн-методы.** Любое продолжение обучения ухудшает эту политику (продолжение SFT −6,1%): как и в [опыте с PPS](FULLSFT-RESULTS.md), дальнейшее next-item обучение портит частотный приоритет. Относительно этого контроля Exp-RSFT лучше: +0,0043 NDCG (0,1426 против 0,1382) при λ=0,1, а для секунд +5,6% награды при +0,4 п.п. NDCG. Это направление совпадает с идеей Exp-RSFT, но в абсолюте результат ниже исходной политики; выводов о других системах здесь не делается. Интервал Exp-RSFT − SFT не считался: построчные метрики в этом отчёте не сохранялись.

## Ограничения

Один seed RL, одно окно selection на 36 политик, без поправки на множественность. Судья обучен на тех же логах, что и обучающие RM. Награда — прогноз RM, не наблюдённый отклик; рост секунд не означает реального роста времени прослушивания.
